# Claude post-Stop continuation contract — separate capability acceptance

Effective for the new `claude-stop-continuation` candidate only (2026-09-07). It adds no release API and no quiescence claim. It adds two controls: a **re-check**, which is a read-only observation of current facts and can never return a quiescence verdict, and an **isolated continuation**, which starts a new Attempt in a workspace proven not to overlap any held responsibility. The original workspace is **not** released and cannot be released by this build. Every predicate of the prior revision — NS1 through NS6 included — is unchanged and unweakened; this section adds criteria, it revises none.

The 2026-09-05 section above belongs to the `claude-native-stop-product` candidate and is not edited here. Its NS3 and its closing sentence ("No residual quiescence/release API is added in this revision") remain true of that candidate.

| New criterion | Required observation | Relationship to the prior revision |
| --- | --- | --- |
| CR1 | The packaged GUI names the blocked work: task, campaign goal, exact workspace path, operation id, bound input UUID, interruption time, a standing Core reason, the residual state and the available choices; each rendered value equals the corresponding Core/SQLite value, and the panel remains reachable after the user moves into a continuation workspace, marked as belonging to the source workspace | Adds explanation; changes no state |
| CR2 | A re-check appends one observation per invocation with a strictly increasing sequence, records the identity actually probed, and maps to a five-row domain in which `not-running` is reachable only from a real absent-process observation of a real recorded identity; no quiescence verdict exists in the Rust enum or in the SQLite CHECK | Strengthens NS2: residual state is now re-observable without ever becoming a safety claim |
| CR3 | One complete path on the final build: real native turn, native Stop, held, re-check, continuation into a non-overlapping workspace, and real Runtime tool activity there — with no manual database edit, development script, prompt replay or pasted transcript, and with the record linked to its source attempt, operation, task and campaign | New capability |

Original-workspace release is **not implemented** and is not part of this contract. Releasing it would expose a silent force-kill (a deterministic attempt id collides with the held attempt, and replacing a `ManagedRuntime` drops and kills its child) and would not make the workspace usable by the original attempt anyway (the adapter's `pending_stop` clear is unreachable). Both are recorded with code sites in `goal-runs/claude-stop-continuation/owner-decision-package.md`.
